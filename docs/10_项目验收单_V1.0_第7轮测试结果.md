## Docker 镜像漏洞检查

最终镜像 `article-reprint-monitor-web:latest`（digest `83a6f0ad142c`）由 Docker Scout 扫描：0 Critical、1 High、0 Medium、0 Low，镜像约 86 MB、145 个包。

唯一 High 为 `mariadb 11.8.8-r0` 的 `CVE-2025-13699`。Scout 的 Alpine 数据显示“<= 11.8.8-r0，未提供修复版”；但 MariaDB 官方 CVE 清单显示该 CVE 已在 Community Server 11.8.4 修复。运行镜像内的 `mysqldump --version` 已实测为 11.8.8，因此按上游版本应为已修复，判定为扫描器包元数据误报。该结论必须在后续镜像更新时重新核验，不能通过忽略扫描规则隐藏告警。

运行镜像已使用非 root `appuser`，并具备可写 home 目录；Python 依赖审计与数据库备份均在该权限模型下实际通过。MySQL 和 Redis 没有发布宿主机端口；`web:8000` 和 `frontend:5173` 为本机开发暴露端口，不可直接复用为生产暴露策略。

## 安全结论

SQL 注入、XSS、CSRF、SSRF、DNS rebinding、内网/云元数据访问、文件上传、路径穿越、Excel 公式注入、越权、暴力登录、密钥扫描、日志脱敏、CORS 和 Docker 敏感服务端口均已有自动化或配置级检查。`CVE-2025-13699` 的扫描告警已经根据官方已修复版本和实际版本完成证据化判定，但 Docker Scout 本身仍会显示该条 High，属于持续监控项。

## 最终结论

**不允许上线。** 目前没有未判定的 Critical 漏洞；唯一 High 扫描告警已按官方版本信息判定为误报/已修复版本，但生产验收仍缺少真实平台 KPI、恢复演练、真实 SMTP、持续运行和生产网络验证。完成这些项目、由责任人签署原始验收单后，才可进行上线批准。
